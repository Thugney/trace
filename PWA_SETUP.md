# PWA Setup Guide - Family Learning Hub

## Overview
Family Learning Hub is configured as a Progressive Web App (PWA), allowing it to be installed on devices and work offline.

## What's Configured

### ✅ PWA Features Implemented
- **Service Worker**: Auto-generated by vite-plugin-pwa with Workbox
- **Web App Manifest**: Configured in `vite.config.ts`
- **Offline Support**: Caching strategies for API, images, and fonts
- **Install Prompts**: Users can install app on their devices
- **Auto Updates**: Service worker automatically updates when new version is deployed

### ✅ Caching Strategies
1. **API Calls** (`NetworkFirst`)
   - Tries network first, falls back to cache
   - 24-hour cache expiration
   - 10-second network timeout

2. **Images** (`CacheFirst`)
   - Caches images for 30 days
   - Up to 60 images cached

3. **Fonts** (`CacheFirst`)
   - Caches fonts for 1 year
   - Up to 30 font files cached

## Icon Setup

### Current Status
The app includes an SVG template icon (`frontend/public/icon.svg`) with the Family Learning Hub branding.

### Generate PWA Icons

#### Option 1: Using npm script (Recommended)
```bash
cd frontend

# Install sharp (one-time)
npm install sharp

# Generate all icons
npm run generate:icons
```

This will create:
- `pwa-192x192.png` (Android PWA)
- `pwa-512x512.png` (Android PWA large)
- `apple-touch-icon.png` (iOS home screen)
- `favicon-32x32.png` (Browser tab)
- `favicon-16x16.png` (Browser tab small)

#### Option 2: Manual generation
See `frontend/public/ICONS_README.md` for detailed instructions on using ImageMagick or online tools.

#### Option 3: Custom icons
Replace `frontend/public/icon.svg` with your own design and regenerate.

## Testing the PWA

### Local Development
```bash
# Build the app
cd frontend
npm run build

# Preview production build (required for PWA features)
npm run preview
```

Then visit http://localhost:4173 and:
1. Open DevTools > Application > Service Workers
2. Verify service worker is registered
3. Open Application > Manifest to see PWA details
4. Test "Add to Home Screen" in Chrome mobile or desktop

### Production Testing
After deploying to your Synology:
1. Visit your app URL (https://yourdomain.com)
2. Look for browser install prompt (Chrome: address bar icon)
3. Install the app
4. Test offline: Turn off network, app should still load cached pages

## Deployment on Synology Docker

### Docker Configuration
The PWA is designed to work with your existing Docker setup. No special configuration needed.

### HTTPS Required
PWAs require HTTPS in production. Ensure your Synology reverse proxy or web server is configured with:
- Valid SSL certificate
- HTTPS enabled
- Proper headers for service workers

### Verification Checklist
After deployment:
- [ ] App loads over HTTPS
- [ ] Service worker registers (check browser DevTools)
- [ ] Install prompt appears
- [ ] App can be installed to home screen
- [ ] Offline mode works (cached pages load without internet)
- [ ] Updates deploy automatically

## Customization

### Change Theme Color
Edit `vite.config.ts`:
```javascript
theme_color: '#YOUR_COLOR_HEX'
```

Also update in `index.html`:
```html
<meta name="theme-color" content="#YOUR_COLOR_HEX" />
```

### Change App Name
Edit `vite.config.ts`:
```javascript
manifest: {
  name: 'Your Custom Name',
  short_name: 'Short Name'
}
```

### Modify Caching Behavior
Edit the `workbox` section in `vite.config.ts`. See [Workbox documentation](https://developers.google.com/web/tools/workbox) for advanced options.

## Troubleshooting

### Service Worker Not Registering
1. Check browser console for errors
2. Ensure you're using `npm run preview` (not `npm run dev`)
3. Verify HTTPS in production
4. Clear browser cache and reload

### Icons Not Showing
1. Generate icons: `npm run generate:icons`
2. Rebuild: `npm run build`
3. Hard refresh browser (Ctrl+Shift+R)

### Offline Mode Not Working
1. Check DevTools > Application > Cache Storage
2. Verify service worker is active
3. Test with DevTools > Network > Offline checkbox

### Updates Not Deploying
1. Service worker caches aggressively
2. Users may need to close all app tabs
3. Consider implementing update notification UI
4. Can manually unregister old SW in DevTools
